# Harness Agent Team

基于 DeepSeek Harness 的可配置多模型 Agent 项目团队。仓库：`yuanxuguang/harness-agent-team`（私有），主分支：`main`。

用户在统一群聊入口交流，由可配置的团队完成需求理解、任务拆分、开发、测试、返工和结果反馈；项目背景、任务进度与后续计划持续保存，支持跨会话交接。

## 当前状态

本仓库当前提供完整架构方案、配置示例和实施检查表。业务服务、群聊接入、共享记忆及原生运行器适配器均待实施，尚无可运行的应用或部署结果。仓库建立不代表产品已经上线。

## 核心设计

- **成员可配置**：机器人身份、职责、运行引擎和模型独立设置。任何满足能力与权限条件的成员都可承担负责人、开发、测试或自定义角色。
- **模型按能力选择**：每个机器人选择对应运行器实际支持的模型。使用某厂商模型，不等于运行该厂商的原生编码工具。
- **项目记录统一管理**：背景、已确认决定、任务状态和下一步保存为有来源、有版本的记录；原生会话用于继续执行。
- **群聊和执行分别调度**：用户可以询问进度或调整需求，后台工作按依赖、权限和并发策略继续。
- **交付可核对**：并行写任务使用独立工作区，测试结果绑定具体代码版本，恢复时核对外部操作结果。

## 交给 Claude Code 或其他编码 Agent

先阅读完整架构方案及本仓库开发约定，审核设计与上游实际能力的差距，再进入实现：

1. 核实并记录采用的 Harness、Super-agent 和各原生运行器的版本、提交及协议，固定可复现的依赖组合。
2. 检查方案引用的接口、持续会话、权限、消息流、取消及恢复能力。文档中的建议模块和接口不能当作上游现有实现。
3. 输出有代码或官方资料依据的审核结论，标明可复用、需要扩展和仍未验证的部分。
4. 按实施状态文档推进完整产品目标；每项交付记录改动、实际验证结果、未完成项和下一步。

特别检查原生 Claude Code、Codex 的**适配器能力**与**原生运行器能力**之间的区别。不能仅复用一次性任务封装，就声称已经实现长期负责人或持续协作；以锁定版本的实测结果为准。

当前没有启动命令。确认技术基线并实现可运行模块后，再补充安装步骤、环境变量、启动命令、部署与回滚说明。模型凭据、飞书凭据和服务器密钥通过安全配置提供，不提交到仓库。
