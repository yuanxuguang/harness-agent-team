统一群聊入口；可配置机器人、角色、引擎与模型；多项目和多仓库；后台多任务与成员协作；原生运行器持续会话；共享项目背景、任务进度和后续计划；权限控制；隔离工作区；带代码版本的验证；断线恢复；多设备访问；可观察运行状态和部署运维。

## 优先审核的问题

1. 锁定的 Harness 和 Super-agent 版本有哪些可直接复用的接口？哪些只是文章中的设计？
2. 原生适配器是否能持续会话、接收后续任务和可靠报告终态？封装限制与底层能力是否已分清？
3. 如何确保每个项目只有一套权威任务状态，并防止旧负责人或旧版本写入覆盖新记录？
4. 切换机器人、模型或运行器后，哪些上下文能恢复，哪些需要结构化交接？
5. 权限、代码隔离、测试版本绑定和不确定外部操作核对能否贯穿整个流程？

## 跨会话验收场景

在项目 A 保存已确认背景、一个未完成任务、验证证据与下一步；结束原会话后，由另一成员在新会话读取并核对这些记录，再继续任务。随后修改需求，验证新成员使用新版本计划。另建项目 B，确认不会误读项目 A 的记录。运行结果和失败情形都应保留证据。

## 后续工作记录格式

每项交付记录：任务目标、负责人、需求版本、相关提交、实际改动、实际执行的验证与结果、未完成项、阻塞和下一步。没有执行的检查写“未执行”，没有验证的能力写“待验证”。
